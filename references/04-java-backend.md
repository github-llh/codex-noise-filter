# Java 与 Maven 后端

## 项目与命令

- 优先使用 `./mvnw`，其次使用项目明确指定的 Maven；从 `pom.xml`、`.mvn/`、toolchains 和 CI 确认 JDK/Maven 约束。
- 多模块项目先确认聚合 root、目标 module 和依赖方向。常用最小命令为 `-pl <module> -am`，不要默认全仓构建。
- 使用项目已有本地仓库参数、profile 和测试插件约定；不写死个人 Maven/JDK 路径。

## 分层与契约

- Controller 负责协议适配、基础校验和调用编排；业务判断、跨系统取值、状态流转、聚合组装和持久化访问放在 Service/领域层。
- Service 接口表达业务契约；实现类处理事务、规则和协作。不要为了形式为每个内部类制造接口。
- Request/DTO/VO/Entity/DO 各自承担输入、传输、展示和持久化语义；避免同一对象跨所有层透传。
- 简单字段约束优先 Bean Validation；跨字段或需查库的业务校验放 Service。
- Mapper/Repository 只承载数据访问。动态 SQL 必须保留权限、租户、逻辑删除、分页和索引条件。

## 枚举、配置与映射

- 有限业务状态优先复用领域枚举，并保持数据库/API code 兼容。公共字段暂时为 `String` 时，业务赋值和校验仍应通过枚举 code/lookup 集中处理。
- URL、密钥、超时、重试、阈值、线程池和开关使用类型化配置；默认值必须有业务依据并可验证。
- 重复 DTO/Entity/VO 映射优先项目已有 MapStruct、converter 或 assembler；避免反射型万能拷贝掩盖字段差异。
- Lombok 按项目风格使用；实体和继承模型谨慎生成 `equals/hashCode/toString`，敏感字段不得意外输出。

## 事务与副作用

- 事务边界放在完整业务用例处，明确事务管理器和 rollback 语义。
- 自调用、异步线程、事件监听和多数据源可能绕过代理事务，修改前确认真实调用方式。
- 外部 HTTP、文件、消息和通知通常不可随数据库事务回滚；优先 afterCommit、outbox、可靠消息或项目已有机制。
- 不在长事务内做无界批量、远程调用或阻塞等待。

## 错误与安全

- 保留项目异常体系和错误码，记录必要上下文但不泄露 token、隐私或完整请求体。
- 不绕过认证、授权、数据权限、租户和审计；查询与更新必须使用相同边界。
- 避免 N+1、无分页全量查询、循环单条写入和未限制动态排序/字段名。

## 验证

1. 最快失败检查：目标模块 `compile` 或等价编译。
2. 行为变化：定向测试或目标 Service/Mapper 测试。
3. 公共契约、SQL、事务、权限或消息变化：追加相关模块测试或集成证据。
4. 构建失败先区分 JDK/Maven/profile/module 选择与代码错误。
