# 并发、事务与数据边界

## 并发模型

- 先确认共享状态、并发入口、线程/协程/进程模型和一致性要求，再选择锁、队列、原子操作、版本号或幂等键。
- 不使用无界线程池、队列、重试或批量。线程池要有容量、拒绝策略、监控和关闭生命周期。
- 锁顺序保持一致，缩短持锁时间；不要在锁内做远程调用、文件 IO 或长事务。
- 异步任务必须传播或显式重建必要的用户、租户、trace 和审计上下文，任务结束后清理 ThreadLocal。

## 幂等与重试

- 从业务唯一键、请求 token、消息 id、数据库唯一约束或状态机中选择稳定幂等依据。
- 幂等检查与状态写入要处于同一一致性边界；仅先查再写通常存在竞态。
- 重试只适用于可重试错误，必须限制次数、退避并避免放大下游故障；非幂等副作用默认不自动重试。

## 事务与消息

- 明确数据库提交、消息发布、缓存更新和外部调用的先后关系。
- 需要“提交后发送”时使用 afterCommit、outbox 或可靠消息；失败补偿必须可观测且可重放。
- 消费端按至少一次投递设计去重与幂等；不要假设消息只到一次或严格有序。

## 批量与查询

- 批量操作使用合理 chunk，避免一次性加载全量数据或生成超大 SQL。
- 保留部分失败语义、重试范围和进度记录；不要吞掉单项错误后返回整体成功。
- 性能问题先用查询计划、调用次数、数据量和指标定位；避免凭感觉加缓存或并行化。
- SQL 变更检查索引可用性、选择性、排序、分页、租户/权限和锁范围。

## 验证

- 幂等：重复输入、并发输入、超时重试。
- 事务：异常回滚、提交后副作用、跨数据源边界。
- 并发：竞态、拒绝策略、关闭与上下文清理。
- 批量：空输入、边界 chunk、部分失败和大数据量。
