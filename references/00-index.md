# Reference 索引

本索引负责选择最小必要规则集。先按任务类型路由，再按实际文件、配置和命令追加技术栈规则；产品名和关键词只是线索，不是触发边界。

## 基础路由

| 当前任务 | 必读 | 条件追加 |
| --- | --- | --- |
| 解释代码、回答仓库问题 | `01` | 涉及多文件行为时加 `02`；按技术栈加 `04` 至 `08` |
| 定位报错、性能或错误数据 | `01`、`02` | 要运行命令时加 `03`；并发/事务/数据问题加 `05` |
| 修改、重构或迁移代码 | `01`、`02`、`03` | 按文件证据加 `04` 至 `08` |
| 代码审查或 diff review | `01`、`02`、`03` | 安全敏感内容加 `09`；按技术栈追加 |
| 构建、测试、lint、typecheck、CI | `03` | 按技术栈追加；失败根因不清时加 `02` |

## 路由规则

1. 先用 `rg --files`、项目配置、失败命令和目标路径确认技术栈，不根据用户随口提到的框架加载规则。
2. 同一任务默认加载一个主技术栈文件；只有真实调用链跨栈时再追加。
3. reference 解决的是判断差异，不替代读取真实项目文件、同类实现和项目命令。
4. 已读规则若与当前仓库证据冲突，以更高优先级指令和项目事实为准，并明确冲突。
5. 第三方输出的“完成”或“通过”不能替代当前 diff 和本轮验证。

## 不应追加的情况

- 仅因出现 `Java`、`React` 等词，但当前任务没有对应文件或命令证据。
- 为回答单一事实而加载完整执行、环境和恢复规则。
- 为修复明显单文件语法错误而追踪无关数据库、消息和外部系统。
- 为“更全面”读取所有 reference、全仓日志或所有 Git 历史。
