# 工程基线

本文件适用于所有编程语言、脚本、SQL、配置、模板的读取、修改和审查；未单列的 Go、Rust、C/C++、C#、Kotlin、Swift 等技术栈同样执行本基线。目标是约束范围与风险，不把局部任务扩成全仓治理。

## 范围与工作区

- 先确认 Git root、目标模块、当前分支和 `git status --short`。
- 用户已有改动、未跟踪业务文件和其他工具产生的改动都属于外部状态；不回滚、不覆盖、不混入本轮格式化。
- 只读取能定位目标、完整语义单元、直接依赖和验证入口的文件。搜索优先 `rg` / `rg --files`，命中后收窄。
- 新建文件前查同职责文件、模块边界和依赖方向；不编辑 `dist/`、`build/`、`target/` 等可重建产物来掩盖源问题。

## 修改授权

- “解释”“审查”“诊断”默认是只读任务；只有“修复”“实现”“调整”“重构”等请求授权写入。
- 不因阅读时发现代码味道就自动扩改。旁支问题只有在阻断当前目标、与根因处于同一最小闭环，或用户明确授权时才纳入。
- 新增依赖、公共 API/DTO、数据库、权限、路由、配置键、对外协议和不可回滚副作用需要显式影响评估；超出原范围时停止并请求方向。

## 读取完整性

- 修改前读取完整函数、类、组件、配置块、SQL statement 或脚本入口，不只看 diff 附近几行。
- 仅在需要解释行为时追直接调用方、被调方和配置来源。高风险契约、历史兼容或删除逻辑再查最小 Git 历史。
- 使用 `git log -- <file>`、`git blame -L`、`git log -S/-G` 和 `git show` 读取历史；不使用会改工作区的 Git 命令获取历史。

## 代码质量

- 优先复用项目已有枚举、常量、配置、类型、mapper、converter、schema、组件和测试模式。
- 固定闭合集合适合枚举或联合类型；协议 key 适合契约常量；环境 URL、密钥、超时、重试、阈值和开关适合配置；运行期可维护值适合字典或数据源。
- 写入前扫描字符串、数字、布尔开关、状态、类型、来源、协议字段、路由、事件、缓存 key、时间格式、阈值、超时、重试次数和容量限制。短小且自解释的局部值可以保留；跨层传递、参与分支、重复出现或预期变化的值必须集中表达。
- 只有共同语义稳定、变化方向一致、依赖方向正确且能验证时才抽公共能力。不要用万能工具类、反射、复杂泛型或 `any` 掩盖建模缺口。
- 注释说明业务原因、单位、兼容、安全和副作用边界，不复述代码。仅在公开契约或非显然约束处补充必要注释；新增或修改的注释、docstring 默认使用简体中文，外部协议原文、标准术语和必须保持一致的第三方契约除外。
- 保持认证、授权、租户、审计、事务、异常和错误返回语义；不吞异常、不伪造成功。

## 编码与跨平台

- 保留项目现有编码、BOM、换行和格式化规则，避免整文件重写导致噪声。
- 出现乱码或编码异常时，先查 `.editorconfig`、构建资源编码、HTTP charset、文件 IO 的 `encoding` 和终端 locale；在源头修复，不在业务逻辑里二次转码兜底。
- 可分发文件不写个人绝对路径、机器名、真实凭证或生产地址。

## 修改后检查

1. diff 是否只包含任务相关文件。
2. 行为变化是否与目标一致，公共契约是否保持兼容。
3. 是否引入硬编码、重复逻辑、过宽类型、无界重试或额外副作用。
4. 新增或修改的注释是否使用中文，魔法值是否按业务语义归入枚举、常量、类型、配置、字典或 design token。
5. 是否存在乱码、不可见方向控制字符、trailing whitespace 或意外格式化。
